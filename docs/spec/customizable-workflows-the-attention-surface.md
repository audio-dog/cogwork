### 12. The Attention surface

Settled in [Prototype: the attention inbox for Workflow parks and approvals](https://github.com/taylorfsteele/cogwork/issues/794) and landed on mock data in [#795](https://github.com/taylorfsteele/cogwork/pull/795).

- **One Attention page**, switched between a board and a list with Tabs (`?layout=`), three lanes: **Needs you**, **Notified**, **Skipped**. Every card opens in place (`?focus=<id>`); nothing opens a separate screen. The surface is one client of the command RPCs and holds no state of its own beyond per-item drafts (edited agent text, a note, a chosen answer) that survive a layout switch.
- **Card, closed:** reason icon, title, two lines (the reason's text when it has one, else the element summary), reason label, time, a "changed since it parked" mark, the source. **Card, open:** a lineage line ("From Weekly product sync · Granola → Issue r4 · Extract") that opens to every hop across Workflows; the frozen plan as one Trace line per step (pending, done, failed, skipped with its reason); agent text or the error under its step.
- **Approval:** a prompt under the plan — "Run N steps?", the digest, the revision it was built on, Reject, Approve; Edit and Hand back in a menu. Edit turns agent text into fields, and the digest follows the edit. **Handed to you:** one button per answer; a choice whose Transition needs empty input asks for it first. **Other parks:** Hand back with a note; `missing-operation` also links to the Workflow. **Notifications:** summary, matched answers, created artifacts, item link, Dismiss. **Skipped:** one card per Workflow.
- **OS notifications.** Every park raises one, `handed-to-you` included; a click opens `/attention?focus=<id>`. The mechanism, from [research on OS notifications](https://github.com/taylorfsteele/cogwork/blob/research/os-notifications/docs/research/os-notifications.md) and #788 item 9: the main-process Electron `Notification` API (`UNUserNotificationCenter` since Electron 42); the renderer decides when one is due, because it folds the Board, and sends a typed request over the Typed IPC seam; `main` shows it, keeps a reference to every live one in one module (a garbage-collected `Notification` is removed), and stays a dumb pipe for RPC. The `id` carries the item reference (≤ 64 characters; Electron 43 has no custom payload on macOS); a click shows the window and sends the route to the renderer; no Approve button on the banner. The first call into `Notification` happens when a person switches on a Workflow that can park, not at boot; a `failed` event means "not allowed or not signed" and the app points to System Settings. On launch the app reads `Notification.getHistory()` and the `ready` event's `launchInfo`. "Open at login" is opt-in. The daemon never posts an OS notification; to reach the person with no app running it opens the app through a `cogwork://` URL. One constant serves `setAppUserModelId` and the build's `appId` (`com.scribehow.cogwork`). Dev builds are ad-hoc signed and will report `failed`; fall back to the in-app list.
- **The side-panel Attention tab** reads the same park set after the cut-over; whether it folds into the page or stays as the narrow view is a build decision for the cut-over pull request.
